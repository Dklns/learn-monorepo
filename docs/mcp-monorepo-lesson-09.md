# 第 9 课：部署闭环——把只发生在磁盘上的最后一环走完

日期：2026-09-20
前课：docs/mcp-monorepo-lesson-08.md
关联速查：docs/mcp-monorepo-cheatsheet.md 第 5 节（两条变更链路）
状态：讲义已下发；等待用户执行部署并提交线上 URL 与现象。

## 1. 这课补什么洞

第一阶段唯一的证据缺口：A、B 的产物只存在于本机磁盘（21:06 构建的那批 `dist`），
"部署上线"从未真实发生。本课目标：

1. 亲手把一个 `dist` 交给静态托管服务，让线上 URL 返回页面；
2. 亲眼确认部署的是**产物文件**，托管方从头到尾不知道 packages/shared 的存在；
3. 重走一次变更链路，验证"线上用户什么时候才能看到新结果"。

## 2. 准备与选择

- 托管服务选 Netlify Drop（网页拖拽，最快闭环，免费账号即可）。
  也可换成 Vercel / Cloudflare Pages，步骤同理，讲义以 Netlify 为准。
- 注意：需要注册第三方服务账号；不涉及本项目敏感信息，上传的是公开的构建产物。

## 3. 步骤

### 第 1 步：确认产物最新

在仓库根目录执行，确保 dist 反映 shared 当前源码：

```bash
pnpm --filter @learn/shared run build
pnpm --filter "@learn/app-*" run build
```

### 第 2 步：部署 A

1. 打开 https://app.netlify.com/drop ，注册/登录；
2. 把 `apps/a/dist` 文件夹整个拖进网页；
3. 等待上传完成，记下分配的线上 URL。

### 第 3 步：验证线上结果

1. 打开线上 URL，确认显示 ￥12.300；
2. 开发者工具 → Network → 刷新，找到 `index-*.js` 请求：
   它就是托管服务交给浏览器的全部东西——里面已经打包了 shared 的逻辑；
3. 想硬核实：把线上 JS 的 URL 粘到新标签页打开，Ctrl+F 搜 `toFixed(3)`。

### 第 4 步：部署 B（独立部署的实物证据）

同一账号，再建一个站点拖 `apps/b/dist`，记下第二个 URL，
确认显示 ￥99.900。两个 URL 彼此独立，这就是"A、B 分别部署"的样子。

### 第 5 步：变更实验（本课核心）

1. 改 `packages/shared/src/index.ts`（例如去掉 ￥ 或改回 toFixed(2)）；
2. 只执行 `pnpm --filter @learn/shared run build`；
3. 刷新两个线上 URL：变了吗？（预期：不变——线上是旧产物的快照）
4. `pnpm --filter "@learn/app-*" run build` 后再刷新线上 URL：变了吗？（预期：仍不变）
5. 把 A 的新 dist 重新拖到 Netlify（站点 → Deploys 里重新拖拽或用 Drag & drop），
   刷新 A 的线上 URL：现在变了吗？B 呢？

## 4. 提交内容

- 两个线上 URL（可打码）与各自显示值；
- 第 5 步每一步刷新后线上"变 / 不变"的记录；
- 最后一问的答案：为什么重建了应用产物、线上还是旧的？

## 5. 证据边界

- 线上页面现象以用户报告为准；教师无法访问外部托管服务，
  但会在用户提交后读取本地 dist 核对内容与时间线。
- 本课不涉及自定义域名、CI 自动部署、预览部署等进阶话题，留给第二阶段 CI 单元。

## 7. 实验结果与教师核对（2026-09-20）

### 用户报告（原话）

- 步骤 5 三个观察：1 没有变化；2 没有变化；3 都改变了。
- 拖拽观察：“拖拽上传时，我交出去的是 A/B 对应 index.html 和其中引用的资源文件的压缩包”。

### 教师实际文件核对

| 项 | 结果 |
| --- | --- |
| packages/shared/src/index.ts | 已改回 `￥${amount.toFixed(2)}`，公共接口未变 |
| packages/shared/dist（22:30） | 已重建，内容与源码一致 |
| apps/a、apps/b dist（22:31） | 已重建，产物含 toFixed(2) 与 ￥；文件名哈希更新为 index-BL-VMbBl.js / index-_Po8pDVk.js |

### 教学判定

- 三步现象与预期完全一致：只重建 shared 线上不变；重建应用产物线上仍不变；重新拖拽部署后才变。构建与部署是两个独立环节，线上站点是“上次上传产物的快照”。
- “都改变了”的成立前提是 A、B 的 dist 都重新上传了；每个站点只在自身文件被重新上传时更新，A 的部署不会带动 B。
- 拖拽观察正确：交付的只是 dist 内的 index.html 与哈希资源文件（压缩包是 Netlify 的打包形式），托管方全程未接触 packages/shared、workspace 配置或源码；shared 逻辑已被打包进哈希 JS 内部。
- 本课完成，第一阶段唯一缺口（部署从未真实发生）已补上；部署链路由“复述正确”升级为“亲手走通”。
- 证据边界：线上 URL 与页面显示为用户报告，教师未访问外部服务；以本地 dist 时间线与内容交叉验证。
