## 1. 本课目标

先不配置 pnpm workspace，不安装工具。先能区分“共享代码”“协同修改源码”和“部署应用”三个问题。

切入点：用户已经提出“公共仓库＋tag＋两个应用引用具体版本”的方案。它本身是可行方向，不需要先否定它才能学习 monorepo。

## 2. 两种布局

### 多仓库：通过版本连接独立仓库

```text
shared 仓库：公共逻辑，版本 v1
       ↑ 引用 v1               ↑ 引用 v1
应用 A 仓库                  应用 B 仓库
       ↓                          ↓
部署 A                        部署 B
```

箭头向上表示应用依赖公共代码；不限定通过 Git 依赖还是包注册表消费。

公共函数的参数改变时，沿用显式版本消费方案，通常需要：

```text
修改 shared → 提供新版本／新引用
             → A 更新引用并调整调用 → 验证 A
             → B 更新引用并调整调用 → 验证 B
```

好处：A、B 可以按自己的节奏采用新版本，例如 A 使用 v2，B 暂留 v1。
成本：如果三处频繁协同变化，就需要协调多个仓库中的提交、评审、版本引用和联调。自动化可以降低成本，但不消除这些边界。

### Monorepo：同仓库内组织多个项目

```text
一个 Git 仓库
├── apps/a             ──依赖──┐
├── apps/b             ──依赖──┤
└── packages/shared    ←───────┘

A 的构建产物 → 部署 A
B 的构建产物 → 部署 B
```

假设两个应用已声明本地 workspace 依赖：可以在同一个提交／PR 中修改 shared、A 和 B，一起评审并验证一致的源码状态；部分内部联调不必先把 shared 发布到远程再升级引用。

注意：目录名 apps、packages 是常见约定，不是定义。只把文件夹搬进同一个仓库，不会自动完成依赖声明、构建配置或验证流程。monorepo 也允许使用已发布的包，并不是所有同仓项目都必须共享代码。

## 3. 真正改变的是什么

Monorepo 不只是让代码能复用，更重要的收益之一是降低跨项目协同修改的成本。

需要付出的代价包括：共享改动可能影响更多项目；需要明确依赖边界和验证范围；仓库级权限、构建规模和团队协作也可能更复杂。

因此，它不是天然比多仓库高级。项目经常一起改、一起验证时，合仓可能更有价值；项目联系很弱、需要严格隔离权限时，合仓未必划算。这些是判断维度，不是无例外的规则。

## 4. 暂时分清三个边界

| 边界 | 回答的问题 | 本例 |
| --- | --- | --- |
| Git 仓库 | 源码与提交历史放在哪里？ | 可以一个仓库，也可以三个仓库 |
| 包／应用 | 谁依赖谁，各自负责什么？ | A、B 消费 shared；同仓不取消它们的职责边界 |
| 部署 | 哪些构建产物在何时上线？ | A、B 仍可分别部署 |

源码可以一起提交，不等于线上必须一起发布；同一次源码提交，也不等于线上自动同步更新。

以本课的普通前端静态构建为例，共享代码会被打入应用产物。仓库里的代码变了，不会改写此前已经部署的 JS 文件。运行时远程加载共享模块是另一种机制，本题不采用。

## 5. 理解检查（已作答）

情境：A 和 B 是两个 React 应用，位于同一 monorepo，都通过本地 workspace 依赖使用 shared 中的 formatPrice。它们分别构建、分别部署，共享函数在构建时打入各自的 JS 产物。

今天修复 formatPrice 的小数位显示 bug，函数接口不变。修改已合并，但只重新构建并部署了 A。

问题：B 的线上页面会立即获得修复吗？为什么？如果希望 B 也获得修复，还需要做什么？

题目原先要求用 2–4 句话解释，不要求命令；以下保存用户作答与教师反馈。

### 用户原始回答

> B 的线上页面不会立即获得修复，因为只是修改了本地的 B，没有重新构建并部署到远程。如果希望 B 也获得修复，则需要重新构建 B 并部署到远程。

### 反馈

结论和处理步骤正确：B 的旧产物不会因仓库源码变化而自动更新，要使用修复后的代码重新构建并部署 B。

表述校准：本次实际改的是共享包 shared，不一定修改了 B 自身源码；B 的旧 JS 产物仍包含旧逻辑。应区分共享源码、消费方源码和构建产物。

判断：静态构建场景下的部署边界基础理解检查通过。未检查实际操作，尚未据此判断所有架构取舍都已掌握。
