# 第 17 课（单元 4 续）：真实发布——把 dry-run 跳过的检查层全部兑现

日期：2026-09-21
前课：docs/mcp-monorepo-lesson-16.md
状态：已下发，等待用户提交三道预测题。

## 1. 问题背景

lesson-16 用 dry-run 完成了模型建构，但有三项留档未实测：private 拦截、
登录鉴权、scope 所有权检查。本课真发一次——不是为了让包被人用，而是把
"发布"从预演变成亲手走通，并补上 lesson-09 部署链路、lesson-04 包入口、
lesson-16 版本模型三条线的收口实验：仓库外消费方真实安装。

发布对象是练习包：scope 用什么名字、要不要长期维护，不影响本课结论。

## 2. 概念图：发布链路的检查分层

dry-run 只排练了"打包 + 上传模拟"，真实发布时每一层都可能拦你：

```text
① 本地文件层    private: true → 直接拒绝（lesson-16 只在文档里见过）
② 本地 git 层   工作区不干净 / 未提交 → 拒绝（可用 --no-git-checks 跳，不建议）
③ 网络与鉴权层  registry 指向、未登录 / 2FA → 拒绝
④ 服务端所有权层 scope 不属于你、包名冲突、403 → 拒绝（到达这层才与 npm 服务器对话）
⑤ 上传与落地    tarball 上传 → dist-tag latest 指向它 → 包页可访问
```

lesson-15/16 反复出现的原则再次生效：**检查在哪一层，取决于动作在哪一层发生**。
本课新增的一层是 ④——所有权检查只存在于服务端，本地怎么试都测不出来。

## 3. 预测题（只作答，先不动手）

1. 现在仓库里 `private: true` 已经复位。如果你保持它不动、直接真实运行
   `pnpm publish`（假设已切源、未登录），报错会在第几层被拦、报错内容是关于
   什么的？这和 dry-run 时的行为为什么不同？
2. 如果 `learn` 这个 scope 在 npm 上不属于你（被占用或需要组织权限），
   `pnpm publish` 会在第几层被拦？你猜报错长什么样？如果真被占用，把包改名成
   `@<你的用户名>/shared`，monorepo 内要动几个文件、仓库外消费方要动什么？
   这说明"命名空间"在两个世界里分别是什么成本？
3. npm 对 **scoped 包**（@xxx/yyy）默认 `--access restricted`（私有），而免费
   账号不能发私有包。不加 `--access public` 直接发会发生什么（在第几层、
   什么报错）？另外：shared 当前版本号是 `1.0.0` 且从未发布过——首次发布
   直接用 1.0.0 有没有问题？发布之后，A、B 仓库内的 `workspace:*` 需要改成
   `^1.0.0` 吗，为什么？

### 教师判定

| 题 | 判定 | 说明 |
| --- | --- | --- |
| 1 | 层级判断待实测 | 用户押 ③ 未登录；教师认为 private 是本地文件检查（①），不需要任何网络就能判定，应先于登录被拦。实现顺序不凭文档断言——动手第 3 步本身就是裁决点 |
| 2 | 前半通过，后半不会 | 层级 ④ 正确（所有权只存在服务端）；报错方向对、确切文案以实测为准。改名成本由教师补讲（见下） |
| 3 | 通过 | 服务端拒绝（④）正确，免费账号发 restricted 的真实文案实测兑完（预计 402/403 类）；1.0.0 起步无问题、workspace:* 不改的理由（本地链接、两套声明互不干扰）抓住核心 |

### 改名成本补讲（预测题 2 后半）

- monorepo 内：改 shared 的 name + A、B 两处依赖声明 + pnpm install 更新锁文件 = 3 个 package.json，同一次提交原子完成——正是第一课讲过的“同仓支持把共享实现和调用方调整放同一次提交”。
- registry 世界：包名不可改名。旧名永久占用，只能 deprecate 旧包指向新包；所有仓库外消费方各自改依赖键、重装、验证。
- 结论：命名空间改名在仓库内是廉价的原子重构，在 registry 世界是永久性事件——两个世界的“删除/改名”语义完全不同（本课第 6 节不可逆提醒的根源）。

记录性质：题 1 层级分歧保留，以动手第 3 步实测裁决；其余同前。

## 4. 动手预告（预测点评后进行；账号操作自理，不需要向教师提供凭据）

1. 预检：浏览器打开 `https://www.npmjs.com/~learn`，确认 scope 是否存在；
   注册 npm 账号、开启 2FA；
2. 切源：项目根新建 `.npmrc`（或改用户级），指向 `registry.npmjs.org`；
   跑一次 `pnpm install --frozen-lockfile` 确认锁文件仍然成立（观察点：
   锁文件里存的是完整性哈希还是源站 URL，切源会不会破坏它）；
3. 兑现 ①：保持 `private: true` 真实运行 `pnpm publish`，记录报错原文；
4. 去掉 `private`，按预测题 3 的结论补齐参数，完成首次发布；
5. 仓库外验证（收口实验）：在仓库外目录 `npm init -y` 后
   `npm install @learn/shared`，写三行代码调用 `formatPrice` 并运行；
   观察：安装的包里有什么文件（对照 lesson-16 的 files 白名单）、
   锁文件里把你的包解析成了什么版本范围；
6. 可选：`npm dist-tag ls @learn/shared`；发一个 `next` 标签体验多版本并存。
